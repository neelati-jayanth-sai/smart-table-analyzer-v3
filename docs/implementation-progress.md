# Implementation Progress

## Completed

- Foundation: package layout, configuration, compact metadata-derived `TableContext`, schema compression, and identifier-like classification.
- Persistence: SQLite runs, immutable per-run `Rxxx` results, reports, and replayable safe progress events.
- Deterministic execution: reviewed static local/IOMETE templates, validated tools, snapshot scope, timeout/retry handling, local/production contract tests, and identifier-column rejection.
- Local/IOMETE parity hardening: removed `LIMIT` from `get_partition_layout` so distribution stats use the full population; cast Iceberg snapshot-summary strings to BIGINT in `get_snapshot_history`; made `get_manifest_stats` aggregations NULL-safe and content-filtered (data vs delete manifests); made `get_delete_file_stats` `total_delete_records` NULL-safe. Added contract parity tests for >limit partitions, real string summaries, and NULL counts, plus template/binder tests.
- Benchmark coverage (Architecture.md §41): added deterministic, multi-symptom, production-style local Iceberg tables — `orders_bad_spec`, `orders_day_partitioned`, `events_partition_candidate`, and `customer_orders_identifier_heavy` — plus Docker-local deterministic tests for each symptom and the critical invariants (no identifier scan, no broad profile, metadata-first). Added `docs/benchmark-expectations.md` separating what deterministic tests prove from what live Investigator judgment must prove.
- Investigator and knowledge: bounded lexical/path-safe knowledge access, report contract/reference validation, and injected Pydantic-AI/callback Investigator seam exposing only tools, results, and knowledge.
- Investigator model configuration: legacy `LOCAL_OLAMMA_API_KEY` is normalized as a secret; a custom Pydantic AI v2 native Ollama Cloud adapter uses `/api/chat` with model pinned to `gpt-oss:120b-cloud` (an explicitly set local daemon uses Pydantic AI's Ollama provider with the local `gpt-oss:120b` tag, since `-cloud` is hosted-only — never another vendor/model). No fallback model/provider; keys never appear in logs/events/results.
- FastAPI + UI: table-only run API, in-process lifecycle/cancellation, SSE replay, report/results endpoints, and vanilla HTML/CSS/JS UI.
- Local environment: MinIO + Iceberg REST Docker compose, PyIceberg catalog provider, benchmark seed/reset scripts, and configuration validation.
- Review fixes: canonical table identity, strict result snapshot validation, no fabricated empty-table snapshot, quote-safe DuckDB literals, per-run Investigator creation.
- Root-cause E2E refinement: a compact exact report contract is supplied to the Investigator; knowledge is unavailable before R001+ evidence; expected structured-output failures normalize to safe observable `report_rejected` events without persisting raw model output. A real Docker-local run completed with R001–R004 and a persisted, validated small-files report.
- Report-quality guard completion: deterministic report validation additionally enforces (a) every cited knowledge path must have been actually read in this run via a persisted `knowledge_read` event (a search hit is not a read), (b) citation typing for startup metadata facts — current partition spec / sort order evidence must include R000, current property values R000 or the IOMETE `get_iomete_maintenance_config` measurement — and (c) every report cites at least one stored measurement (R001+; R000 alone is not table evidence). Integration callback fixtures now read cited knowledge through the real tool path and cite R000 for metadata currents; focused unit tests cover each rule plus valid-report persistence through the store. Architecture.md §32 records the rule set.
- Verification: **386 tests passing** (unit 313, contract 18, integration 38, benchmark 9, scripted e2e 8). Two warnings remain: the architecture-required `QueryResult.schema` field shadowing a Pydantic `BaseModel` attribute, and a harmless PyIceberg parquet-writer-option notice emitted while seeding benchmark tables.
- Model-transport failure hardening (verified root error path from the final live E2E: the configured Ollama Cloud key reached the native `/api/chat` endpoint and was rejected with HTTP 401): Pydantic AI `ModelHTTPError`/`httpx` transport failures now normalize to a typed, safe `ModelTransportError` at the `PydanticAiInvestigator` seam; RunService emits a safe `model_failed` event and a run error describing the authentication/configuration failure — never the response body, key, endpoint, or raw model output. The `report_rejected` distinction is preserved. Unit tests cover 401/403/other-status/unreachable normalization and event-payload secrecy; integration tests drive the 401 and connect-error paths through the real run lifecycle and SSE stream.
- Live-run report-defect fixes (model reasoning only, no deterministic diagnosis engine): the Investigator prompt/compact contract now require quoting curated standards exactly and judging compliance strictly against the read range (a configured value outside it is a deviation, not compliance), require metadata metrics before targeted candidate analysis for materially considered non-identifier temporal columns (and forbid `insufficient_evidence` before that measurement), and distinguish a small absolute file count from material fragmentation (no remediation without runbook materiality criteria). Scripted investigator regressions (`tests/e2e`) assert the metadata-first tool-selection order end-to-end and that the delivered prompts carry the rules; prompt rule unit tests live in `tests/unit/investigator/test_prompt.py`. `docs/benchmark-expectations.md` records the three observed live-run defects and the updated live-scenario expectations.
- Property-casing benchmark coverage: added `demo.orders_bad_spec_caps_properties` — the deliberately bad `hours(event_timestamp)` spec plus deliberately inert UPPERCASE custom property keys — with deterministic tests proving uppercase keys are preserved byte-for-byte as inert metadata, surfaced with raw casing in the compact TableContext and R000, and never confusable with effective lowercase keys (only the exact lowercase keys drive derived facts such as metrics availability); prompt rules state that property-key casing is significant. Truthful framing is pinned in `docs/benchmark-expectations.md`. After the corrective rules above, live Docker-local runs of `local.demo.orders_bad_spec` and `local.demo.orders_bad_spec_caps_properties` both completed with persisted, validated reports (`R000`–`R002`, knowledge reads, evidence-cited findings). Curated runbooks now cover file-sizing, maintenance, partitioning, and sort-orders.
- Operator/developer documentation: added `docs/current-state.md` describing what works now, exact local startup/UI commands and sample fully-qualified tables, investigator/model configuration (gpt-oss cloud/local tag distinction), deterministic tool/partition-candidate behavior, result/SSE/report guarantees, current test count and warnings, validated benchmark tables, and known limitations/blocked production validation.
